## 🌟 项目特性

1. **零构建依赖（No-Build Architecture）**：
   - 采用纯现代标准 Web 技术栈（HTML5 + CSS3 + 原生 ES6 + Python 3 标准库）。
   - 无需 npm install、无需 Webpack/Vite 编译打包，克隆即用，免除依赖地狱。
2. **硬核工业级科技美学**：
   - 深空科技蓝视觉基调、CSS 呼吸微光晕、3D 泵模型透视展示、关键指标数据带（KPI Strip）。
   - 响应式自适应布局，完美适配 PC 桌面端、平板电脑及智能手机（配备抽屉式移动导航）。
3. **数据解耦与 CSV 直接驱动**：
   - 页面全站文案、板块内容块（图片 / 表格）、企业资质、展示图片均由 `data/content.csv` 驱动，技术人员与非技术人员均可通过 Excel、记事本或管理后台随时编辑。
4. **开箱即用的可视化管理后台（`/admin.html`）**：
   - 内置可视化内容管理器，支持实时修改**全站所有文字**（Hero 首屏、指标看板、表单标签等 73 个文案字段）、增删板块内容块（图片 / 表格）、自定义图片显示尺寸、拖拽裁剪图片（集成 Cropper.js）、主题色定制、卡片角标编辑等。
   - **全站图片统一管理控件**：Logo、首页背景大图、首页装备主图、企业营业执照，以及产品/性能/使用/应用/联系五大板块背景图，均采用同一套「上传 / 替换 / 删除」控件。按钮文案随状态自动切换（未上传时显示 `⬆️ 上传图片`，已上传后显示 `🔄 替换图片` 并出现删除按钮）；上传前支持拖拽裁剪。
   - 「首页与通用文案」Tab 内置**首页图片**分组，集中管理首屏背景大图与右侧装备主图；删除背景大图后自动回退到 Hero 渐变底色，删除装备主图后自动恢复内置装备图。
   - 后台顶部**标签栏名称可自定义**：7 个标签的文字（含「客户询盘管理」等）均可在「首页与通用文案 → 🧭 后台标签栏名称」中重命名，仅影响后台界面；清空即恢复默认名称。
   - **前台导航栏名称可逐项编辑**：网站前台顶部导航菜单（桌面端 + 手机端抽屉同步）可在「首页与通用文案 → 🌐 前台导航栏名称」中逐项改文字、增删项数；全部清空保存则恢复默认五项导航。
   - **板块内「内容块」自由增删与排序**：四大板块的每一块内容都可是**图片块**或**表格块**，支持添加 / 删除 / 上移 / 下移，图文自由混排；图片块可设自定义显示宽高（`200` / `200px` / `50%` 均可，纯数字按像素处理；**只填宽度时高度按原图比例自动缩放**），可选「裁切填满 / 完整缩放」填充方式，卡片文字与角标随尺寸同步收缩，缩到极小也不会被内容撑开；表格块为**空白网格起步**（初始列 / 行数可调），可增删行列、逐格编辑、指定高亮列或选择不高亮；**任何板块都不预置表格**。
   - **页面零内置展示模板**：原内置的「竞品参数对标表」「客户实绩墙（4 家客户卡片）」「产学研体系（3 大支柱卡片）」均已彻底移除。前台只渲染您在内容块里自行添加的图片块与表格块，系统**不会向任何板块自动注入**任何展示内容（也不存在把历史文案自动转成展示块的一次性迁移）。
   - **上传的图片不会被后续保存抹掉**：内容块的图片在「💾 保存所有更改」时先落盘到 `images/`，再把最终路径回写到编辑器；之后无论再保存多少次、切换到哪个板块再保存，已上传的图片路径都会自愈保留，不会回退成默认图。
   - 提供直接一键落盘保存到服务器磁盘或导出 CSV 功能。
5. **智能工况选型与询盘管理系统**：
   - 专为工业制造研发的工况参数表单，支持介质类型（熔盐、液态铅铋合金 LBE、强酸碱等）与温区（350℃~850℃）选型提交。
   - 询盘数据自动安全归档在 `data/inquiries.json`，并在后台提供可视化的询盘管理面板。
6. **国家级资质认证展示**：
   - 集成营业执照官方认证卡片与高精度原件 Lightbox 全屏放大画廊。
   - **资质展示为数据驱动、留空即隐藏**：未上传营业执照时执照卡片不出现、也不进入画廊；未填写统一社会信用代码时联系卡片中不出现该条目。想恢复只要把值填回去即可，无需改代码。

## 🏗️ 系统架构与核心工作原理

### 1. 整体分层架构图

```text
+-------------------------------------------------------------------------+
|                  Web 客户端 (PC浏览器 / 平板 / 智能手机)                    |
+-------------------------------------------------------------------------+
                                    |
                                    v
+-------------------------------------------------------------------------+
|                 前端轻量化交互层 (Vanilla Web Standards)                  |
|  - 视图渲染 (index.html / admin.html)                                    |
|  - 现代样式与动效 (css/style.css)                                         |
|  - 业务控制器 (js/main.js / js/admin.js)                                  |
|  - 数据引擎核心 (js/data.js -> DataManager)                              |
|  - 图像处理引擎 (Cropper.js)                                              |
+-------------------------------------------------------------------------+
             |                                             |
             v                                             v
+-----------------------------+               +---------------------------+
|       数据与离线缓存层        |               |      后端微服务层 (Python)  |
| - localStorage 浏览器缓存    |               | - server.py 零依赖轻量服务  |
| - 内存响应式字典 (_csvContent)| <---(HTTP API)---> - POST /api/save-content   |
| - 内置默认数据字典 (_defaults)|               | - POST /api/save-image    |
+-----------------------------+               | - POST /api/submit-inquiry|
                                              | - GET  /api/inquiries     |
                                              +---------------------------+
                                                           |
                                                           v
                                              +---------------------------+
                                              |      本地磁盘持久化存储     |
                                              | - data/content.csv (主配置)|
                                              | - data/inquiries.json(询盘)|
                                              | - images/ (高清装备资产)   |
                                              +---------------------------+
```

### 2. 数据驱动核心原理 (Data Layer)

整个网站的数据流转由 `js/data.js` 中的 `DataManager` 单例对象统一调度：

- **数据统一格式**：所有配置采用 CSV 的三列标准结构：`section,field,value`。
  - `section`：板块命名空间（如 `meta`, `product`, `performance`, `usage`, `application`, `contact`, `texts`）。
  - `field`：字段名（如 `section_title`, `section_description`, `text_position`, `blocks`, `hero_title`）。四大板块的图片与表格统一存于 `blocks` 字段（JSON 数组），详见[板块内容块](#板块内容块图片--表格-自由增删与排序)。
  - `value`：字段值。
- **BOM 智能消除与解析**：`DataManager.parseCSV` 为完整状态机解析器，内置 UTF-8 BOM 自动剥离、转义引号（`""`）还原，并支持**带引号的多行字段**（字段内可包含换行符，如多行主标题、表单下拉选项），能够跨平台兼容 Windows Excel、Mac、Linux 生成的各种 CSV 格式。

### 3. 前后端数据流向与落盘机制

1. **前台页面初始化流程**：
   - 页面加载时，`DataManager.init()` 发起异步并发请求检查后端服务状态（`GET /api/status`）。
   - 若后端存在，立即获取最新的 `data/content.csv` 并解析到内存字典 `_csvContent`。
   - `renderPage()` 根据解析后的内容，动态生成产品矩阵、板块内容块（图片 / 表格）及选型表单。
2. **后台修改与持久化落盘流程**：
   - 管理员在 `/admin.html` 中编辑文案或通过 Cropper.js 上传新图片。
   - 点击 **「保存所有更改 (直接落盘)」**：
     - 将配置序列化为标准 CSV 字符串，通过 `POST /api/save-content` 直接覆写服务器上的 `data/content.csv`。
     - 若包含 base64 裁剪图片，通过 `POST /api/save-image` 将二进制数据保存至 `images/` 目录，并自动替换为文件路径引用。
   - 彻底避免了纯前端静态页面“刷新后修改丢失”的痛点。

### 4. 多级高可用容错降级体系

网站设计了**三级数据降级机制**，确保在任何网络环境下均不会白屏：

> **读取优先级**：
> - 已启动 `server.py` 后端时：`data/content.csv (磁盘权威)` -> `localStorage (本地覆盖兜底)` -> `_loadDefaults (内置兜底字典)`
> - 纯静态 / 离线环境时：`localStorage (本地覆盖)` -> `content.csv` -> `_loadDefaults (内置兜底字典)`
>
> 即：**只要后端在运行，手动用记事本 / VS Code 修改 `data/content.csv` 后刷新页面即刻生效**，不会再被浏览器里陈旧的 localStorage 缓存遮蔽。


- **网络断网或纯静态环境**：当没有运行 Python 后端时，`DataManager` 会自动切换为离线模式，利用 `localStorage` 保存修改与离线询盘，页面依然完整可用。
- **缓存版本控制**：内置 `VERSION: "v4_all_texts_editable"` 机制，当系统升级时自动清理过期陈旧缓存，防止用户端出现样式或文案错乱。

## ⚡ 快速开始与本地运行

本项目为零构建依赖架构，只需电脑安装了 **Python 3.6+** 即可一键运行：

### 1. 克隆或下载解压代码
```bash
git clone <仓库地址> magdrive-website
cd magdrive-website/website
```

### 2. 启动本地服务
```bash
# 默认监听 8080 端口（也可指定任意端口，例如 8090）
python3 server.py 8080
```
控制台将提示服务启动，并在浏览器中自动打开：
- 前台展示页：`http://localhost:8080`
- 后台管理页：`http://localhost:8080/admin.html`

  4. **客户询盘管理（📩）**：查看所有通过前台表单提交的意向工况参数（包括客户姓名、电话、选型介质、温区及具体要求），支持按时间排序与一键导出。

## 🛠️ 二次开发与定制指引

### 修改品牌标识与主视觉
- **更换 Logo**：将您的透明背景 Logo 命名为 `logo.png` 并放置在 `images/` 目录下（或直接在 `/admin.html` 后台上传替换）。
- **更换 3D 主图**：将您的三维装备模型或核心产品图片放置在 `images/`，并在 `admin.html` 或 `data/content.csv` 中更新引用。

### 调整核心板块与文案
如需通过代码直接调整，可直接使用 VS Code、记事本等编辑器打开 `data/content.csv`，格式如下：
```csv
section,field,value
meta,site_title,您的公司名称
meta,site_subtitle,您的官方副标题与定位
product,section_title,您的核心产品系列
product,section_description,板块导语
product,blocks,"[{""t"":""image"",""id"":""m1"",""caption"":""产品型号名称"",""desc"":""详细性能与技术优势介绍""}]"
```

> 四大板块（`product` / `performance` / `usage` / `application`）的图片与表格统一由 `blocks` 字段（JSON 数组）驱动，详见下一节。

**全局设置字段与前台位置的对应关系**（后台「网站全局设置」中的同名输入框）：

| CSV 字段 | 前台生效位置 |
| --- | --- |
| `meta.site_title` | 顶部导航栏公司名 + 浏览器标签页标题 |
| `meta.site_subtitle` | 首页 Hero 区主标题下方的**副标题**说明行 |
| `meta.nav_text` | 顶部/移动端导航菜单项（英文逗号分隔） |
| `meta.footer_text` | 页脚版权文字 |
| `meta.header_bg_color` | 顶部导航栏背景色 |
| `meta.hero_bg_color` | Hero 区渐变背景底色 |
| `meta.hero_title_color` | Hero 区主标题文字颜色 |

### 全站文案目录（`texts` 命名空间）

除 `meta` 全局设置外，全站其余所有文字均由 `texts` 命名空间驱动（共 73 个字段，后台「首页与通用文案 ✏️」Tab 及各板块 Tab 内的文案组均可编辑），按功能分为 7 组：

| 分组 | 内容示例 | 后台位置 |
| --- | --- | --- |
| `hero` | 小标语、主标题、描述段、徽章、按钮、浮动标签 | 首页与通用文案 Tab |
| `hero_stats` | 指标看板 5 项的数值/单位/说明（留空自动跳过该项） | 首页与通用文案 Tab |
| `section_tags` | 各板块英文小标签（如 PRODUCT PORTFOLIO） | 首页与通用文案 Tab |
| `cards` | 四大板块的标题与副标题 | 首页与通用文案 Tab |
| `misc` | 管理后台链接、移动端导航标题、页脚文字等 | 首页与通用文案 Tab |
| `contact_info` | 联系条目标题、执照说明（支持占位符模板） | 联系 Tab 底部 |
| `contact_form` | 表单标签、下拉选项、提交按钮与提示语 | 联系 Tab 底部 |

**三种字段语法约定**：

1. **富文本标题**（如 `hero_title`）：字段内换行符渲染为 `<br>`；`**文字**` 渲染为渐变高亮文字。
   ```csv
   texts,hero_title,"高温磁力泵
   **关键装备研发及产业化**"
   ```
2. **表单下拉选项**（如 `form_product_options` / `form_temp_options`）：每行一个选项，`*` 前缀表示默认选中项。
   ```csv
   texts,form_temp_options,"350℃ ~ 500℃
   *500℃ ~ 650℃
   650℃ ~ 850℃"
   ```
3. **执照说明占位符**：`license_desc` 等字段支持 `{legal_person}` `{registered_capital}` `{company}` `{credit_code}` `{phone}` 变量自动替换。

### 板块内容块（图片 / 表格 自由增删与排序）

四大板块（`产品展示` / `性能参数` / `使用方法` / `应用工况`）的内容不再是「固定图片数量 + 写死的表格」，而是一串**可自由增删、可上下移动排序、图文混排的内容块**。

- **编辑位置**：后台对应板块 Tab →「🧩 板块内容块（图片 / 表格 可自由增删与排序）」分组；底部有「➕ 添加图片」「📊 添加表格」两个按钮，每个块右上角有「↑ 上移 / ↓ 下移 / 🗑 删除」。所有调整在点击「💾 保存所有更改」后落盘。

- **数据存储**：每个板块一行 `blocks` 字段，值为 JSON 数组；`JSON.stringify` 不产生真实换行，因此对 CSV 天然安全。
  ```csv
  product,blocks,"[{""t"":""image"",""id"":""m1"",""slot"":1,""caption"":""产品一"",""desc"":""描述"",""badge"":""850℃ 耐温"",""w"":""200px"",""h"":""150px"",""fit"":""contain""},{""t"":""table"",""id"":""b1"",""title"":""参数对照"",""head"":[""对比项"",""本项目""],""rows"":[[""耐温"",""850℃""]],""hl"":1}]"
  ```
  `image_count` 仍然保留（值为图片块数量），仅作为旧版兼容字段。

- **图片块字段**：

  | 字段 | 含义 | 说明 |
  | --- | --- | --- |
  | `id` | 块唯一标识 | 同一板块内不重复，添加块时自动分配（**基于当前块列表计算**，连续添加也不会重号）；图片落盘文件名、未落盘预览的缓存键都以它为后缀，重号会导致多张图互相覆盖 |
  | `src` | 图片地址 | 上传后自动写入 `images/xxx.png` |
  | `caption` / `desc` | 卡片标题 / 描述 | 留空即不显示（不会自动生成任何标题文字），两项都为空时整块文字区不渲染，只显示图片 |
  | `badge` | 卡片左上角角标 | 留空自动隐藏（按板块循环配色） |
  | `w` / `h` | **自定义显示宽 / 高** | 支持 `200`、`200px`、`50%` 等写法（**纯数字自动按像素处理**）；留空则宽度按网格自适应、高度默认 220px |
  | `fit` | 图片填充方式 | `cover`（默认，裁切填满）/ `contain`（完整缩放，图片整体等比缩小、不被裁切） |

  **尺寸自适应的三条规则**：
  1. **只填宽度**（`h` 留空）→ 缩略图高度按图片原始宽高比自动换算，图片始终整体等比缩小、不变形；
  2. **高度填百分比**（如 `60%`）→ 按「相对卡片宽度的比例」换算（父级高度为 auto，百分比高度本身在 CSS 中无效），图片区高度随宽度同步缩放；
  3. **尺寸调小时**卡片内边距、标题字号、角标与放大提示同步收缩，卡片 `min-width` 归零，缩到 80px 也不会被文字内容撑开。

- **表格块字段**：`title` / `subtitle`（表格上方标题与说明）、`head`（表头数组）、`rows`（二维数组，每个子数组一行）、`hl`（高亮列索引，`0` 起；**`-1` = 不高亮**）。后台提供「＋ 添加列 / ✕ 删列 / ＋ 添加行 / ✕ 删行」，增删列时所有行会自动同步补齐或截断单元格。表格块默认整行铺满容器。

- **新建表格一律是空白网格**：点「📊 添加表格」时，先用旁边的「列 / 行」输入框决定初始规模（默认 3 列 4 行，可改），生成的表头、单元格、标题**全部为空**，不含任何示例内容或固定列名。列可以一直删到 0——0 列的表格在前台**不渲染任何内容**（不做任何模板兜底），后台显示「点击 ＋ 添加列 自行创建结构」的引导。

  > **模板不自带任何表格**：早期的内置「竞品参数对标表」（8 行 × 4 列，由 `compare_*` 文案字段驱动）已彻底删除，连同「把旧 `compare_*` 文案自动转成表格块」的一次性迁移也一并移除。现在**没有任何板块会自带表格**，表格完全由您在内容块里添加 / 编辑 / 删除。历史 `compare_*` 文案若仍留在 `content.csv` 中，仅作为遗留字段保存，不会再被渲染或自动变成表格。
  >
  > **模板不自带任何展示区**：原「应用工况」板块末尾自动追加的**客户实绩墙**（4 张客户卡片）与**产学研体系**（3 大支柱卡片）同样已彻底移除——前台渲染函数、后台文案编辑组（原 `showcase` 分组共 25 个字段）与配套 CSS 样式全部删除。板块里显示什么，完全取决于您在内容块中添加了什么。

- **旧数据自动迁移**：若 `content.csv` 中没有 `blocks` 字段（旧版本配置），前端与后台会按旧 `image_count` + `image1_caption` / `image1_description` / `image1_badge` 就地迁移为图片块（id 前缀 `m`），历史图片与文案不丢失；下一次「保存所有更改」即以 `blocks` 形式落盘。迁移结果会被缓存，不会重复计算。

- **块图片地址三级回退**：`刚上传未落盘的 base64 → 块上的 src 路径 → 旧槽位图`。上传图片后输入框被标记为 `UPLOADED`，同一轮保存会在图片落盘后自动把真实路径回填到块 `src`，**因此一次保存即可得到最终路径，无需二次保存**。

### 卡片角标与板块背景图

- **卡片角标**：角标由图片块的 `badge` 字段驱动（旧版 `imageN_badge` 已废弃，首次加载时自动迁移进块内），填写后显示于卡片左上角（按板块循环配色），**留空自动隐藏**。后台在内容块编辑器内逐块编辑。
- **板块背景图**：五个板块（`product` / `performance` / `usage` / `application` / `contact`）支持上传背景图，数据存储在 meta 图片键 `section_bg_板块名`，后台各板块编辑器顶部提供「板块背景图」上传/删除控件；删除后恢复纯色背景。
  ```csv
  meta,section_bg_product,images/section_bg_01.jpg
  ```
  前台渲染时自动叠加浅色半透明渐变蒙版（`linear-gradient`），确保浅色背景上文字依然清晰可读。

### Meta 图片字段总览

所有图片均由 `meta` 命名空间的键值驱动，统一登记在 `js/data.js` 的 `DataManager.META_IMAGE_KEYS` 中：

| 键名 | 用途 | 内置默认值 | 删除后表现 |
| --- | --- | --- | --- |
| `logo` | 导航栏 Logo | `images/logo.png` | 回退齿轮图标 |
| `hero_bg` | 首页背景大图 | 无（使用 Hero 渐变色） | 回退 `meta.hero_bg_color` 渐变 |
| `hero_image` | 首页右侧装备主图 | `images/hero_pump_3d.png` | 恢复内置装备图 |
| `license` | 企业营业执照 | `images/business_license.jpg` | 回退默认执照图 |
| `section_bg_<板块名>` | 五大板块背景图 | 无 | 回退纯色背景 |

**写入策略**：`DataManager.META_IMAGE_DEFAULTS` 中登记的默认值不会被写回 `data/content.csv`，避免配置文件被冗余路径污染；只有用户主动上传/指定的图片才会落盘为相对路径（后端模式下上传的图片文件本体保存在 `images/`，CSV 中仅存路径并自动剥离 `?t=` 时间戳）。

### 后台标签栏名称

管理后台顶部那一排标签（`首页与通用文案` / `产品展示` / `性能参数` / `使用方法` / `应用工况` / `联系信息设置` / `客户询盘管理`）的文字支持自定义重命名，方便按自己的说法调整后台菜单。

- **编辑位置**：后台「首页与通用文案」Tab →「🧭 后台标签栏名称」分组，共 7 个输入框；**仅影响后台界面，不影响网站前台**（网站前台顶部导航栏的文字请在紧邻的「🌐 前台导航栏名称」分组中修改）。
- **数据存储**：`meta.admin_tab_<tabId>`，其中 `<tabId>` 为 `texts` / 四个板块名 / `contact` / `inquiries`。
  ```csv
  meta,admin_tab_inquiries,客户留言
  ```
- **默认值**：登记在 `DataManager.ADMIN_TAB_DEFAULTS`，**与默认值相同（或留空）的标签不会写入 CSV**，配置文件中只保留真正被改过的条目；把输入框清空即可恢复该标签的默认名称。
- **渲染顺序**：`DataManager.ADMIN_TAB_ORDER = ["texts", ...sections, "contact", "inquiries"]`，标签与内容面板均按此顺序渲染；新增板块会自动出现在标签栏中。
- 取值统一走 `DataManager.getAdminTabLabel(tabId)`（自定义值优先，缺省回退默认值），保存后自动调用 `refreshAdminTabs()` 局部刷新标签栏并保留当前选中项。

### 前台导航栏名称

网站前台顶部的导航菜单（桌面端导航条 + 手机端抽屉菜单，两处同步）支持逐项编辑文字、增删项数。

- **编辑位置**：后台「首页与通用文案」Tab →「🌐 前台导航栏名称」分组（紧邻「后台标签栏名称」之下），每项一个输入框，可「＋ 添加导航项」或「✕」删除单项。
- **数据存储**：仍统一存于 `meta.nav_text`（逗号分隔整串），逐项编辑在保存时汇总拼接写回。
  ```csv
  meta,nav_text,"产品展示,性能参数,使用方法,应用工况,联系我们"
  ```
- **跳转规则**：导航项按顺序对应 `产品 → 性能 → 使用方法 → 应用工况 → 联系我们` 各板块锚点，项数与顺序即可控制菜单结构。
- **双编辑入口**：「网站全局设置」中原有的逗号分隔整串输入框保留，作为快速批量修改入口；**保存时若逐项编辑被改动过（dirty 标记）则以逐项编辑为准**，否则整串输入框优先生效，两入口互不覆盖。
- **默认值**：全部清空并保存后 `nav_text` 落盘为空串，前台自动回退内置默认五项导航。
- **注意区分**：此分组修改的是**网站前台**导航；「后台标签栏名称」分组修改的是管理后台自身的标签，两者互不影响。

### 扩展工况选型表单字段
如需增加新的表单字段（如“交货周期”、“预算区间”等）：
1. 在 `index.html` 或 `js/main.js` 的 `renderContactSection()` 中增加 `<input>` 或 `<select>`。
2. 在 `handleInquirySubmit(e)` 中提取字段并放入 `submitInquiry` 参数。
3. 后端 `server.py` 的 `/api/submit-inquiry` 会自动将所有接收到的 JSON 属性完整归档到 `data/inquiries.json`。

## 🚢 生产环境部署指南

### 方式一：Systemd 服务守护 + Nginx / NPM（推荐）

1. **部署文件到服务器**：
   ```bash
   sudo mkdir -p /var/www/magdrive
   sudo cp -r ./* /var/www/magdrive/
   ```
2. **注册开机自启守护进程**：
   ```bash
   sudo cp /var/www/magdrive/deploy/magdrive.service /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable magdrive
   sudo systemctl restart magdrive
   ```
3. **通过 Nginx Proxy Manager (NPM) 配置反向代理**：
   - 登录 NPM Web 控制台，添加 **Proxy Host**。
   - **Forward Hostname / IP**：填 `127.0.0.1`（或 Docker 网关 `172.17.0.1`）。
   - **Forward Port**：填 `8090`（与 `magdrive.service` 中配置一致）。
   - 在 **SSL** 标签页中申请 Let's Encrypt 证书并开启 **Force SSL**。

### 方式二：GitHub Webhook 全自动持续部署（CI/CD）

当您或协作成员将代码推送到 GitHub 仓库时，服务器将自动触发拉取并即时热更新前台：

1. **进入 GitHub 仓库后台**：
   依次点击 **Settings** -> **Webhooks** -> **Add webhook**。
2. **配置 Webhook 参数**：
   - **Payload URL**：`http://服务器IP:8090/api/webhook`（或您的自定义反代域名 `https://your-domain.com/api/webhook`）
   - **Content type**：选择 `application/json`
   - **Secret**：填写服务器端保存在 `data/webhook_secret.txt` 中的密钥（安全隔离，未提交至 Git）
   - **Which events would you like to trigger this webhook?**：选择 `Just the push event`
3. **完成配置**：点击 **Add webhook**，GitHub 将发送一次测试 ping，收到绿色对勾即表示连通！后续每次推送代码均会自动同步并在 `/admin.html` 的「GitHub 自动部署 🚀」面板中查看实时日志。
